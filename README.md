# Кадровый учёт КР — MVP (этапы 0–8)

Flask + SQLite. Реализовано: вход, три роли (admin, hr, manager) с проверкой прав на сервере,
журнал действий, сквозная нумерация документов, хранилище файлов, защита форм от CSRF.

Этап 1 (только администратор): справочники (подразделения, должности с архивированием),
данные организации, нормативные параметры ТК КР в настройках, управление пользователями
(создание, роль, отключение, сброс пароля; нельзя отключить себя или последнего администратора).
Все изменения пишутся в журнал.

Этап 2: сотрудники и кадровая история. Кадровик и администратор создают, редактируют и архивируют
сотрудников (удаления нет), ведут историю (подразделение, должность, оклад, условия, основание),
ищут по ФИО и фильтруют по подразделению и статусу. Руководитель видит только ФИО, подразделение,
должность, статус, дату приёма, телефон и email: остальные поля (паспорт, ПИН, адрес, оклад и др.)
не выбираются из базы для его запросов. Статус «Оформляется» — до приказа о приёме (этап 3).

Этап 3: движок документов и приказ о приёме. Шаблоны хранятся в базе с версиями (раздел «Шаблоны»,
только администратор), поля подставляются по списку допустимых, неизвестные поля отклоняются. Приказ
создаётся как черновик, при проведении атомарно: присваивается сквозной номер (по году), текст
фиксируется (позднейшая смена шаблона его не меняет), сотрудник получает статус «Работает»,
дата приёма и запись в истории. DOCX и PDF скачиваются только у проведённых приказов.
Проведённый приказ не редактируется и не удаляется (исправление: новый приказ).
**Начальный текст приказа — образец**: замените его на форму, утверждённую юристом.
Для PDF в папке fonts лежит шрифт DejaVu (поддержка кириллицы).

Этап 4: трудовые договоры (на движке документов этапа 3). Тип (бессрочный/срочный), даты, испытательный
срок в днях, оклад, режим работы. Проверки: для срочного обязательна дата окончания, испытательный срок
не больше предела из настроек (месяцы от даты начала) и не длиннее договора. Оформление атомарное:
номер (отдельная нумерация договоров по году), фиксация текста, один действующий договор на сотрудника.
К оформленному договору прикрепляется скан (PDF/JPG/PNG до 10 МБ, тип проверяется по содержимому).
Начальный текст договора — **образец**, замените его в разделе «Шаблоны» на утверждённый юристом.
Основания и ограничения для срочных договоров по ТК КР в программу не заложены: их проверяет юрист.

Этап 5: отпуска. Остаток ежегодного отпуска = начислено + корректировки − оформленные ежегодные отпуска.
Начислено = норма из настроек × полных месяцев работы (с даты приёма до начала отпуска) ÷ 12, с округлением вниз.
Корректировки (перенос остатка, исправления) вносятся с обязательной причиной и пишутся в журнал.
Дни считаются календарными, включая крайние даты; праздничные дни внутри отпуска не исключаются.
Превышение остатка: на черновике показывается предупреждение, оформить приказ нельзя. Нельзя пересекать
оформленные отпуска. Приказ об отпуске создаётся при оформлении (общая нумерация приказов, шаблон «Приказ о
предоставлении отпуска»). Статус «В отпуске» вычисляется по оформленным отпускам и сегодняшней дате.
График на год (раздел «Отпуска») и остатки доступны администратору и кадровику.
Правила начисления — допущение, подтвердите их у юриста по ТК КР.

Этап 6: приказы о переводе и о прекращении трудового договора (кнопки в карточке сотрудника).
Перевод добавляет запись в кадровую историю (должность, подразделение, оклад с даты перевода) и
отклоняется, если ничего не меняет. Основания прекращения хранятся в справочнике (раздел «Справочники»,
администратор): названия и ссылки на статьи ТК КР вносит юрист, ссылка попадает в текст приказа.
Проверки по типу основания: по инициативе работника — дата заявления и срок предупреждения из настроек
(иначе «Соглашение сторон»); истечение срока — действующий срочный договор и совпадение даты; иное —
пояснение. В приказ добавляется строка о неиспользованных днях отпуска на дату прекращения (расчёт выплат
вне программы). Статус «В архиве» и прекращение договора наступают в день прекращения (при проведении,
если дата уже наступила); данные и история не удаляются. Предупреждения (не блокируют): нет
действующего договора в системе, есть отпуска после даты прекращения.
Отменить проведённый приказ нельзя: исправления оформляются новым приказом.

Этап 7: напоминания и главная страница. Главная показывает сводку (работают, в отпуске, оформляются,
действующие договоры, черновики) и ближайшие сроки: окончание срочного договора (в том числе просроченное),
окончание испытательного срока, начало отпуска, последний день работы. Горизонт — настройка «Напоминания»
(по умолчанию 30 дней). Руководитель видит сводку и сроки, но не ссылки на договоры и отпуска.
Рассылка: ежедневная команда `flask --app app send-reminders` (cron, Планировщик заданий Windows или облачный
планировщик). Письмо получают активные кадровики и администраторы, у которых указан email (раздел
«Пользователи»); каждый срок отправляется один раз (изменение даты шлёт повторно). Ошибка отправки не
теряет события: повтор при следующем запуске. Кнопка «Проверить и отправить сейчас» есть на главной.

Настройка почты (переменные окружения): SMTP_HOST, SMTP_FROM — обязательны; SMTP_PORT (587 или 465),
SMTP_USER, SMTP_PASSWORD, SMTP_SECURITY (starttls | ssl | none), APP_URL — ссылка на приложение в письме.
Пример cron (каждый день в 8:00): `0 8 * * * cd /app && flask --app app send-reminders`.

Этап 8: приёмка и подготовка к запуску. Сквозной приёмочный тест (8 критериев ТЗ подряд), матрица прав
по всем маршрутам, резервное копирование и восстановление (`flask backup`, `flask restore`), журнал действий
с фильтрами и страницами, смена своего пароля (профиль), блокировка перебора паролей (5 попыток за 15 минут),
заголовки безопасности и запрет кэширования страниц, русские страницы ошибок, срок сессии 8 часов,
обязательный SECRET_KEY в production, режим WAL для SQLite.

## Запуск
    pip install -r requirements.txt
    export SECRET_KEY="длинная-случайная-строка"   # обязательно в проде
    export DATABASE=kadry.db
    flask --app app init-db
    flask --app app create-user admin --role admin --name "Администратор"
    flask --app app run

Тесты: `python -m unittest discover -s tests -v`

## Развёртывание
Серверный пакет готов к размещению: `Dockerfile`, `docker-compose.yml` (приложение + автоматический HTTPS через Caddy),
`deploy/` (systemd, nginx, entrypoint), `.env.example`. Ежедневные задачи (копия в 02:00, напоминания в 08:00)
выполняет встроенный планировщик (`scheduler.py`). Первый администратор создаётся при первом запуске из `ADMIN_LOGIN`
и `ADMIN_PASSWORD`. Подробная инструкция, восстановление, обновление и список непроверенного — в **DEPLOY.md**.

Состав пакета: код приложения в корне, `templates/`, `fonts/`, `tests/` (110+ автотестов), `deploy/`,
`docs/` (ТЗ `PROJECT_SPEC.md`, план `PLAN.md`, приёмка `ACCEPTANCE.md`, вопросы юристу `LEGAL_CHECKLIST.md`).

## Дальше
Готово по плану. Перед запуском: docs/ACCEPTANCE.md (ручная проверка в браузере) и docs/LEGAL_CHECKLIST.md (вопросы юристу).

После обновления с этапа 0 выполните `flask --app app init-db` ещё раз: данные сохранятся, добавятся новые таблицы.
